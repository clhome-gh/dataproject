6. 데이터 품질에서 확인할 점
분석 결과를 활용하기 전에 한 가지 더 점검해야 해.

날짜별 기록 수는 모두 24,288행으로 동일해.

각 날짜에 513개 도로명이 포함돼 있어.

다만 날짜와 요일코드를 비교했을 때, 일부 날짜의 요일 코드가 실제 달력과 맞지 않는 것으로 보여. 요일을 예측 변수로 활용하기 전에 실제 날짜에서 요일을 다시 계산하는 편이 안전해.

그리고 3일간의 평균속도는 각각 약 22.54, 22.63, 22.46으로 비슷했어. 하지만 날짜가 3개뿐이므로 요일이나 날씨 등 외부 요인에 따른 차이를 판단하기에는 부족해.

기초통계 분석의 결론
현재 자료에서는 도로 유형별 평균속도에 차이가 있었고, 시간대별로도 뚜렷한 변화가 나타났어. 특히 퇴근 시간대의 평균속도가 가장 낮았다는 점은 앞으로 출퇴근 시간대와 평시를 비교하는 탐구의 출발점이 될 수 있어.

다음 단계로는 전체 평균만 보는 데서 나아가 같은 도로의 출근·평시·퇴근 평균속도를 비교하는 것이 좋아. 그래야 도로 유형 자체의 차이와 시간대에 따른 변화를 구분할 수 있어.

5. 군집 분석

도로별 평균 속도·중앙값·속도 변동을 기준으로 도로를 비슷한 특성끼리 분류. 군집 수를 2~8개 범위에서 선택

실행 방법
ZIP 파일을 내려받아 압축을 풀어.

main.py와 requirements.txt를 같은 폴더에 둬.

그 폴더에서 터미널을 열고 아래 명령어를 실행해.

pip install -r requirements.txt
streamlit run main.py

4. 앱이 열리면 왼쪽의 파일 업로드에서 **1시간 소통정보 (도로별-방향별).csv**를 선택해.

컬럼 이름을 자동으로 찾아보도록 만들었지만, 데이터 파일의 실제 컬럼명에 따라 왼쪽 메뉴에서 도로명·시간·속도 컬럼을 직접 지정해야 할 수도 있어.

참고로 회귀 분석은 시간과 속도의 관계를 단순 직선으로 살펴보는 것이고, 군집 분석은 비슷한 속도 특성을 가진 도로를 묶는 것이야. 분석 결과는 실제 CSV를 업로드해야 계산되며, 아직 네 데이터 파일을 이 코드로 직접 실행해 검증한 결과는 아니야.

이번 오류는 main.py에서 사용하는 Plotly 라이브러리가 설치되지 않아서 발생했을 가능성이 높아. 코드 자체보다는 requirements.txt 설정을 먼저 확인하면 돼.

2. Streamlit Cloud에서 다시 실행하기
GitHub에서 requirements.txt를 수정하고 Commit 해.

Streamlit Cloud에서 앱을 열어 줘.
